# Data (not stored in the public repository)

The public repository contains code, reports, the slide deck and small result tables (`data/derived/*.csv`) but **not the raw inputs**.
Everything below is regenerated by the scripts and `make`; only the FunFam inputs need to be obtained separately.

| Input | Where it comes from | How to get it |
|---|---|---|
| UniProt entries, sequences and annotations | UniProt REST API | `make data` (script 01) from the frozen accession list `data/raw/uniprot/accessions.txt`; scripts 07, 08, 22, 26 fetch further entries (cached under `data/raw/uniprot/`, `data/raw/orthologues/`) |
| AlphaFold models | AlphaFold Protein Structure Database | `make data` (script 02) and `scripts/02_fetch_structures.py --universe` |
| Experimental structures (PDB) | RCSB PDB | `scripts/16_experimental_benchmark.py` downloads up to 3 entries per gene |
| CATH FunFam alignments and metadata (`data/raw/christina/`: `FF_alns/`, `funfam_metadata.csv`, `human_abhd_funfam_hhalign_matrix.csv`) | CATH FunFam resource for superfamily 3.40.50.1820, prepared by a collaborator | **Not public here.** CATH provides FunFam alignments for this superfamily; the metadata CSV (FunFam id, human UniProt members, gene names) and the HHalign E-value matrix must be recreated or requested. Scripts 06, 07, 09 and 12 need them. Regenerating them from CATH has not been tested. |

Large generated files (`data/derived/domains/`, `*.npz`, ProtBert tensors) are rebuilt by the scripts. UniProt content changes over time; fetch dates are
recorded where scripts cache downloads (for example `data/raw/uniprot/third_source_fetched.txt`), so exact numbers may drift on a fresh run.
